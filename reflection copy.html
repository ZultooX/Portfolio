Overview

This page breaks down the internal architecture of the Eclipsed Game Engine. The focus is on how systems are structured, why decisions were made, and how subsystems interact.

Rendering System

The rendering pipeline is built on top of OpenGL and designed around a modular frame graph approach to allow future API abstraction.

Design Goals

  • Minimal CPU overhead
  • Batch-friendly architecture
  • Future Vulkan compatibility

Implementation

Rendering is split into stages: geometry, lighting, and post-processing. Each stage is decoupled to allow reordering and experimentation.

Entity Component System (ECS)

The ECS is designed for cache-friendly iteration and fast entity lookup using sparse sets.

Why ECS?

Traditional OOP approaches created tight coupling. ECS allows data-driven design and better performance scaling.

Structure

  • Entity ID (uint32)
  • Component pools
  • System processors

Asset Pipeline

The asset system pre-processes resources into engine-ready binary formats to reduce runtime overhead.

Tooling System

Tools are built using ImGui and tightly integrated into runtime systems, allowing real-time debugging and modification.
